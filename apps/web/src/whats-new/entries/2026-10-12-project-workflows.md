title: Several workflows per project, and your own steps in Code
date: 2026-10-12
audience: admin
help: /help/projects#workflows
---
A project can now run **more than one workflow**. In the project's settings, under **Workflows**, enable another workflow, say which card types it is the default for, and the **New card** form lets you pick when a type has two choices. You can also **customise** a workflow for one project: the Code steps stay as they are, and you insert your own after any of them (a security check after Build, an investigation after Test). The new version goes to the desk for the owner's approval before any card uses it; running cards finish on the version they started on, and **Rebase** applies your steps to a newer Code version. Organization Owners and Admins enable workflows and create variants; the BA can draft a variant in a design chat.
