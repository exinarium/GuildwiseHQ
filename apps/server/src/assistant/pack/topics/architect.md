### The architect: investigate and design
The optional design step before build, investigation-only cards, where reports go, the main branch merge, and what the architect may touch.
- Turning it on: 1. Hire an architect (Agents, Hire agent, role Architect). It costs more per shift than a builder. 2. Open the project's settings, Architect, tick Investigate & design before build on new cards and Save.…
- Investigation-only cards: Tick Investigation only for an answer, not a change (a comparison, "how should we ...", a spike). Nothing is built: the architect writes the report, the BA records the result in the ledger and in the project's PROJECT.md, and the card is done.…
- Where the report goes: By default a markdown file in the repository, docs/investigations/<ref>-<title>.md, merged with the card. In the Architect settings you can change the folder or choose the knowledge vault instead (nothing is committed; the card finishes without a merge).…
- Merge the latest main branch first: When a repository has a main branch and a different working branch, the runner merges main into the working branch before work starts (on by default; a project or card can switch it off). If the working branch is protected or changed meanwhile, the card branch takes the merge.…
- What the architect may touch: - It writes only documentation and its report; the runner checks this after each shift. - It reads the card's repository and every repository of the organization's projects cloned on its workstation, read-only, secret files blocked.…
- Organisation source folder: Open Workstations, expand your workstation and find the row Organisation source folder (only the workstation's owner sees it; it is set per organization, for the one you are working in). The architect may read every repository in the folder, read-only; secret files stay blocked.
