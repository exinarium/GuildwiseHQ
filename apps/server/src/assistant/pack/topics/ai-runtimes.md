### AI runtimes and accounts
Sign in to Claude Code, Codex and the Gemini CLI, set API keys, and give a project its own account.
- Which runtimes: Claude Code, Codex, the Gemini CLI, opencode, and direct APIs: Anthropic, OpenAI, Gemini, any OpenAI-compatible endpoint, and Claude Code on Amazon Bedrock, Vertex AI or a gateway.
- Accounts: Each runtime and provider has one main account and any number of named accounts, per workstation. Use Add a named account and give it a short name such as work. The main account is what the CEO, DevOps and chats that are not about a card use.…
- Sign in: Sign in runs the program's own login on the workstation. Open the link, enter the code (Codex) or paste the code (Claude, Gemini), and the account shows Signed in. Each named account keeps its login in a folder of its own, so two accounts never mix.…
- Keys: Set key encrypts the key in your browser for that workstation's runner, which keeps it. This needs HTTPS or localhost. A named account is your own key, so it is not capped.…
- Sharing: A named account belongs to one workstation and spends its owner's own key or login. Allow projects to use my accounts (on the AI runtime section, off by default) lets projects you are not a member of pick your named accounts;…
- Make main: Make main swaps a named account with the main account. Nothing is lost, and doing it again undoes it. It works the same for every provider, Claude Code included.…
- Per project: In a project's settings, Accounts for other providers (and Claude account) choose which account the project's tickets use. If the account is out (usage limit, login or key), the tickets pause, or use the main account if you ticked the fallback box.…
