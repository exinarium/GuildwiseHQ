TOCMARK_s12x2_12.2 The independent security review and its fixes

A separate review looked at the whole system as an attacker would, with agents treated as untrusted. It found high, medium and low issues. Every one was fixed with a test, in these commits:

FindingProblemFix
H1A manager of a shared project could add standing orders for the owner's organizationStanding orders need project or organization ownership
H2, M3, M4Agent sessions were not confined: environment, per-role permissions, writable files, read-only rolesSandboxed sessions with a minimal environment, per-role Claude permissions, a generic writable-glob guard, and read-only roles are rolled back
H3Deactivating a user left their runners, memberships and agents workingDeactivation unlinks the runners, removes memberships and parks the agents
M1, M5, M7Owner-controlled refs, URLs and paths could reach git and the file systemValidation of refs, URLs and paths; runner paths are confined; URLs with credentials are refused; card refs and worktree paths are unique
M2An agent's permissions could be widened beyond its rolePermissions may only narrow the role definition
M6, M8, lowHardening items: response headers, chat rights, runner command ownership, outbound leak check, rate limits, log redaction, links, archived-agent hireCSP and HSTS, chat re-checks on every message, runner command ownership, the outbound leak check, rate limits, log redaction, lease-preserving projection rebuild, http(s)-only links, archived-agent hire check

The threat model and what the sandbox does and does not protect against are written down in docs/RUNNER.md, section "Threat model and residual risk".

TOCMARK_s12x3_12.3 The real Claude Code smoke run

The test suites use the mock runtime. A real Claude Code shift was run once on Linux, in the sandbox, with AOM_CLAUDE_SMOKE=1 (this spends tokens, see docs/RUNNER.md). It found four problems that no mock could show:

Failure foundCauseFix
No writable temporary directoryThe allowed read of the agent directory also covered the writable home and scratch; bubblewrap re-opens an allowed read read-only over the binds beneath it, so every Bash call failed on its first writeAllowed reads no longer include directories that hold writable paths; every agent gets a private tmp (TMPDIR, TMP, TEMP, CLAUDE_CODE_TMPDIR); agent sessions no longer inherit the runner's whole environment
node hidden by the read blockSandboxed commands lose read access to /home under blockReadsOutsideWorkingDirectories, so Node and the aom shim were unreachableThe runner's Node install and the configured toolchainPaths are re-opened for reading
The aom exclusion patternThe exclusion used a bare aom, which only matches the command without argumentsExclude aom * and the shim's absolute path; aom runs outside the sandbox because Linux blocks Unix sockets inside it
Session tools such as ListAgentsSession-level tools (ListAgents, SendMessage and others) ran under the dontAsk modeSession tools are denied by name
Result After these fixes a real Claude Code builder shift on a small repository completes inside the sandbox: it writes code, commits, and hands off through aom. The commits are 366f825 and dca3389.
Not covered The smoke run was done on Linux (the same sandbox WSL2 uses). A real Claude on macOS (Seatbelt) and on native Windows has not been run; see chapter 13.

TOCMARK_s12x4_12.4 How the screenshots of this guide were made

The Playwright project guide in e2e/ builds a fake demo world through the real API and the mock runtime: an organization owner (Pieter Demo), a second manager (Maya Demo) on a shared project, three projects (WEB code, SHOOT research, NEWS feed), hired agents of every role, cards in every column, desk items of every kind, ledger entries, enough shift history for HR statistics and recommendations, one workstation that reports no OS sandbox, and a custom workflow. It then drives the real UI and takes every picture at 1280 pixels wide, and the phone pictures at 390 pixels. The project is excluded from pnpm e2e; docs/guide/README.md has the exact commands.
