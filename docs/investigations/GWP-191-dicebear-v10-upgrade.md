# DiceBear 10 upgrade for the web app's generated faces

## Question

The web app draws agent and user faces in the browser with DiceBear 9 (`@dicebear/core`, `@dicebear/lorelei`,
`@dicebear/notionists` and `@dicebear/open-peeps`, all `^9.4.2`). The server stores a seed and a style for each face.
Can we move to DiceBear 10 so that every stored seed still gives exactly the same face?

**Short answer: no.** DiceBear 10 draws a different face for every seed we tried, in all three styles. No supported
option brings the 9.x faces back. We stay on 9.x (outcome B). Nothing changes in the packages, the stored seeds, the
`AvatarStyle` values or the avatar endpoints.

## How the app uses DiceBear today

- `apps/web/src/lib/faces.ts` is the only code that imports DiceBear. It lazy-loads `@dicebear/core` and one style
  module, then calls
  `createAvatar(style, { seed, backgroundColor: BACKGROUNDS, backgroundType: ['solid'], radius: 0 }).toDataUri()`.
  `BACKGROUNDS` is seven hex colours without `#`.
- Callers: `components/Face.tsx` (`useFaceUri` / `faceUri` / `loadFaceStyle`, through `Face`, `AgentAvatar` and
  `UserAvatar`), `components/AgentFacesSync.tsx` (`preloadFaces`), `components/profile/AvatarPicker.tsx` and
  `test/avatar-picker.test.tsx`.
- Seeds come from `randomAvatarSeed()` in `packages/shared/src/avatars/index.ts`: 8 base-36 characters, stored by the
  server (hire, DevOps hire, CEO provisioning, recommendations, reroll). A user's seed is limited to 1–64 characters.

## What DiceBear 10 changes for this app

Versions checked: 9.x = `@dicebear/core@9.4.3` with the three style packages at `9.4.2` (the versions in
`pnpm-lock.yaml`). 10.x = `@dicebear/core@10.7.0` (the `latest` tag) with `@dicebear/styles@10.6.0`.

| Area | 9.x (today) | 10.x | Effect on this app |
| --- | --- | --- | --- |
| Packages | One package per style: `@dicebear/lorelei`, `@dicebear/notionists`, `@dicebear/open-peeps` | **The style packages have no 10.x release** (their `latest` is still 9.4.2, and they need `@dicebear/core ^9`). All styles are JSON files in one new package, `@dicebear/styles` (`@dicebear/styles/lorelei.json`, …) | We cannot "bump all four packages to v10". The three style packages would be swapped for `@dicebear/styles`. |
| Render API | `createAvatar(styleModule, options)` returns `{ toString, toJson, toDataUri }` | `createAvatar` is gone. You call `new Avatar(new Style(definitionJson), options)`, which has `toString()`, `toJSON()` and `toDataUri()`. Passing a raw definition to `Avatar` is deprecated and goes away in 11 | `faces.ts` must be rewritten: `Core['createAvatar']` no longer exists, so the file does not even typecheck. |
| Background options | `backgroundColor` (hex with or without `#`), `backgroundType: ['solid' \| 'gradientLinear']`, `backgroundRotation` | `backgroundColor`, `backgroundColorFill: 'solid' \| 'linear' \| 'radial'`, `backgroundColorAngle` | `backgroundType` is **refused** with `OptionsValidationError: /backgroundType has an unexpected property`. |
| Corner radius | `radius` (0–50) | `borderRadius` | `radius` is **refused** in the same way. |
| Component option names | `hair`, `glassesProbability`, … | `hairVariant`, `glassesProbability`, … | We set none today. |
| lorelei components | beard, earrings, eyebrows, eyes, freckles, glasses, hair, hairAccessories, head, mouth, nose | Same names and the same number of variants | Same catalogue. The choice per seed is different (see below). |
| notionists components | base, beard, body, bodyIcon, brows, eyes, gesture, glasses, hair, lips, nose | head, beard, **clothes**, **clothesGraphic**, **eyebrows**, eyes, gesture, glasses, hair, **mouth**, nose | Five components renamed. The default chance of `clothesGraphic` went from 75 to 50 (`bodyIconProbability` was 75). |
| open-peeps components | accessories, face, facialHair, head, mask | accessories, **expression**, facialHair, head, mask | `face` renamed to `expression`. |
| Colour names | per style (`hairColor`, `skinColor`, …) | per style, plus new ones (`outlineColor` for lorelei, `inkColor`/`paperColor` for notionists and open-peeps) | — |
| Output: SVG | `<svg … viewBox="0 0 980 980" fill="none" shape-rendering="auto"><metadata …>` | Same root plus `aria-hidden="true"` and a `<!-- Generated by DiceBear -->` comment. The body is built differently | Markup is never byte-equal. |
| Output: data URI | `data:image/svg+xml;utf8,<encodeURIComponent(svg)>` | `data:image/svg+xml;charset=utf-8,<…>` | Fine for `<img src>`. The string is still different. |
| Seed → face | Sequential xorshift PRNG: a hash of the seed, then one draw per decision in a fixed order | New key-based PRNG (FNV-1a + Mulberry32): each decision is hashed from the seed **and a key**, and lists are sorted before picking. The same output is promised across all language implementations | **A different face for every seed** (evidence below). |
| Size (gzip, rough, from the package files) | core ≈ 4.7 KB; lorelei ≈ 49 KB, notionists ≈ 119 KB, open-peeps ≈ 104 KB | core ≈ 47 KB (it now bundles option and style validators); lorelei ≈ 36 KB, notionists ≈ 114 KB, open-peeps ≈ 95 KB (JSON) | Each style chunk gets a little smaller, but core grows by about 42 KB gzip. Core is loaded with the first face on every page, so this is a noticeable growth. |
| Support | `v9-lts` tag. 9.4.3 came out on 2026-07-05, after 10.0.0 (2026-05-27) | `v10-lts` = 10.5.0, `latest` = 10.7.0. 11.0.0 release candidates are already out (`next` = 11.0.0-rc.2) | 9.x is still maintained, so staying on it is a supported choice. |

### Why "v10 breaks the avatars" happened before

Dependabot PR #12 (`chore(deps): bump @dicebear/core from 9.4.3 to 10.7.0`) bumped **only** `@dicebear/core`, because
the style packages have no 10.x release. That left the 9.x style modules, which need `@dicebear/core ^9`, next to a
10.x core that has no `createAvatar`. Faces could not render, and the bump was taken back out in
"fix: repair CI after the dependency bumps". The repository has no Dependabot `ignore` entry for DiceBear, so the same
major PR will come back.

## Seed determinism: the evidence

Method (run in a scratch folder, not in the repository): install 9.x and 10.x side by side. For each seed and style,
render with the app's exact options: 9.x `createAvatar(style, { seed, backgroundColor: BACKGROUNDS, backgroundType: ['solid'], radius: 0 })`,
10.x `new Avatar(new Style(def), { seed, backgroundColor: BACKGROUNDS, backgroundColorFill: 'solid', borderRadius: 0 })`.
Compare the chosen parts (9.x `toJson().extra`, 10.x `toJSON().options`), compare the markup, and draw both SVGs at
128 px with resvg. A pixel counts as different when the summed RGB difference is above 24.

Seeds: `agent-ada`, `k3x9q2mz` (server format), `0a1b2c3d`, `Zoë Ångström-Ñúñez 李雷` (non-ASCII),
`a-very-long-seed-value-0123456789abcdefghijklmnopqrstuvwxyz-012345` (long, 66 characters), and in the markup run also `9f3c2b1e7d4a`
and the empty seed.

**Markup:** 0 of 21 SVGs are equal.

**Parts chosen for the same seed** (two examples, all others look the same):

| Style, seed | 9.x | 10.x |
| --- | --- | --- |
| lorelei, `agent-ada` | background `#c0aede`, hair variant23, head variant04, eyes variant07, eyebrows variant06, nose variant01, mouth sad09 | background `#fff1a8`, hair variant01, head variant03, eyes variant17, eyebrows variant04, nose variant06, mouth sad07 |
| notionists, `k3x9q2mz` | background `#d1d4f9`, body variant18, hair variant34, lips variant04, nose variant20, eyes variant03, brows variant05, gesture pointLongArm, bodyIcon electric | background `#ffd5dc`, clothes variant15, hair variant23, mouth variant03, nose variant08, eyes variant04, eyebrows variant05, no gesture, no graphic |
| open-peeps, `agent-ada` | background `#d5f0c8`, head medium2, face old, accessories glasses4, skin `#ae5d29`, clothing `#e279c7` | background `#fff1a8`, head noHair1, expression eatingHappy, no accessories, skin `#694d3d`, clothing `#ffcf77` |

**Pixels at 128 px, 9.x against 10.x with the same seed:**

| Seed | lorelei | notionists | open-peeps |
| --- | --- | --- | --- |
| `agent-ada` | 78.5 % differ | 87.8 % | 95.5 % |
| `k3x9q2mz` | 71.5 % | 82.1 % | 96.5 % |
| `0a1b2c3d` | 73.8 % | 79.6 % | 91.2 % |
| `Zoë Ångström-Ñúñez 李雷` | 74.9 % | 16.8 % | 96.2 % |
| long seed | 77.3 % | 77.0 % | 96.6 % |

Side by side, every one of the 15 is plainly a different person: different hair, face, clothes and background colour.

**Can options restore the 9.x face?** No 10.x option selects the 9.x algorithm. The only way is to work out each 9.x
choice ourselves and force it in 10.x with `<component>Variant`, `<component>Probability: 0|100`, `<color>Color` and a
single `backgroundColor`. As a test, we took the 9.x choices from `toJson().extra` and forced them into 10.x:

| Seed | lorelei | notionists | open-peeps |
| --- | --- | --- | --- |
| `agent-ada` | 3.45 % differ | 0.31 % | 0.54 % |
| `k3x9q2mz` | 3.70 % | 0.62 % | 0.62 % |
| `0a1b2c3d` | 3.68 % | 0.35 % | 0.70 % |
| `Zoë Ångström-Ñúñez 李雷` | 4.56 % | 0.29 % | 1.10 % |
| long seed | 4.36 % | 0.26 % | 1.04 % |

The faces are then recognisably the same, but they are **not pixel-equal**. The differences sit along every outline
(the 10.x artwork is placed slightly differently, most of all in lorelei). The markup is also never equal. And to make
the faces in a browser, without 9.x, we would have to copy into our own code 9.x's PRNG, its option defaults and enum
order, each style's pick order and its background pick. That is about 400 lines of library internals that we would
own from then on. It does not meet "pixel/markup-equivalent", so it does not count as "a supported option restores the
v9 output".

## Options

1. **Stay on 9.x and hold DiceBear majors in Dependabot (recommended, outcome B).** No package or data change. Add a
   fixed-seed render test with 9.x fixtures, so any future bump that changes a face fails CI instead of reaching users.
   Add a Dependabot `ignore` for `@dicebear/*` semver-major, with a comment that links this note. 9.x patches,
   including security fixes, still arrive. 9.x is an LTS line that is still maintained.
2. **10.x with a 9.x compatibility layer.** Copy the 9.x selection logic into `faces.ts` and force the choices in 10.x
   (as in the test above). The faces look the same, but there are still sub-pixel differences, about 400 lines of
   copied internals to maintain, core grows by about 42 KB gzip, and 11.x is already in release candidates. Not
   recommended, and it would not meet the card's equivalence bar.
3. **10.x and accept new faces.** The simplest code: about 15 changed lines in `faces.ts`, swapping three packages for
   `@dicebear/styles`. Every agent and user with a generated face looks different after the deploy. This needs an
   **owner decision** to accept the change (and a release note telling users). No re-seeding migration would help: a
   9.x face cannot be reached from any 10.x seed.
4. **Re-seeding migration.** Rejected. 10.x has no seed that gives back a given 9.x face, so a migration cannot keep
   faces. It only makes sense together with option 3, and option 3 does not need it.

## Recommendation

Option 1. Keep `^9.4.2` for all four packages and change nothing in the lockfile. Add the 9.x fixture render test and
the Dependabot major hold that links this note.

To use 10.x later, one of these is needed:

- **An owner decision to accept new faces** (option 3). Then the work is: swap the three style packages for
  `@dicebear/styles`, rewrite `faces.ts` to `new Avatar(new Style(def), { seed, backgroundColor, backgroundColorFill: 'solid', borderRadius: 0 })`,
  re-capture the fixtures, remove the Dependabot hold, and check the bundle-size growth (core ≈ +42 KB gzip).
  Preferably do this straight on 11.x once it is stable, so faces change only once.
- **Or an owner decision to own a 9.x compatibility layer** (option 2), accepting sub-pixel differences.

Bundle size before and after: unchanged, because outcome B changes no package.
