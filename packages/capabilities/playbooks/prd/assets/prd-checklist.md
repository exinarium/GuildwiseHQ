# PRD validation checklist

Answer pass, fail or not applicable for each item, with a reason.

## Purpose
- [ ] The problem is stated in terms of a real user and a real cost.
- [ ] Each goal has a measure, a target and a date.
- [ ] Non-goals are listed.

## Requirements
- [ ] Every requirement has an identifier and a priority.
- [ ] Every requirement is one testable statement, not a bundle.
- [ ] Every must requirement has an acceptance criterion in a testable form.
- [ ] No requirement says how to build it unless the how is a real constraint.
- [ ] Every requirement traces to a goal or a user scenario.
- [ ] No two requirements contradict each other.
- [ ] Terms are defined once and used the same way everywhere.

## Completeness
- [ ] Each user type has at least one scenario.
- [ ] Error cases, empty states and permissions are covered.
- [ ] Non-functional needs are measurable.
- [ ] Dependencies and constraints are listed.
- [ ] Rollout and measurement are described.

## Readiness
- [ ] Open questions each have an owner and a next action.
- [ ] No placeholder text remains.
- [ ] The owner has read the whole document and approved it.
- [ ] The document links to its source sessions and briefs.
