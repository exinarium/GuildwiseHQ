# Governance

This document describes how Guildwise HQ is run: who decides, how work is accepted, and what to expect from the project.

## Roles

- **Maintainer.** Pieter Jordaan ([@exinarium](https://github.com/exinarium)) is the project's author and maintainer. The maintainer decides what is merged, what is released, and how the project is directed.
- **Contributors.** Anyone who opens an issue, starts a discussion, reviews a pull request or submits a change. Contributors follow [CONTRIBUTING.md](CONTRIBUTING.md) and the [Code of Conduct](CODE_OF_CONDUCT.md).
- **Community.** Users who ask questions and share ideas in [GitHub Discussions](https://github.com/exinarium/GuildwiseHQ/discussions).

## Decisions

- **What gets merged.** The maintainer decides. A pull request that meets the contribution rules is not automatically accepted. Maintainers may ask for changes, or decline a change that does not fit the project's direction, and they will explain why when they can.
- **Features.** Ideas start in Discussions, or as feature-request issues. The maintainer decides what goes on the roadmap.
- **Releases.** The maintainer decides when to release. Only the latest release receives security fixes (see [SECURITY.md](SECURITY.md)).
- **Security.** Vulnerabilities are handled privately, and the aim is a fix within four weeks before public disclosure.
- **Changes to this document.** Changes are made by pull request, and the maintainer decides them.

## Support

Support is provided **on a best-effort basis**. There is no guaranteed response time, and no service-level commitment for the open-source project. Help from other users in Discussions is welcome.

Guildwise Cloud customers receive support as described in their plan. Setup, custom workflows and custom agents are quoted separately (see the [README](README.md)).

## Community spaces

- GitHub Discussions is the place for questions, ideas and conversation.
- A Discord server may be added later. This document will be updated when it is.

## Participation

Everyone participates under the [Code of Conduct](CODE_OF_CONDUCT.md). Maintainers may hide, lock or remove comments, issues and pull requests that break it.

## Forks

The code is licensed under Apache 2.0, so anyone may fork it. Forks must follow [TRADEMARKS.md](TRADEMARKS.md): they must use a different name and logo.
